## watch out these rules

# Before implementing anything substantial, inspect the existing codebase.

# Do not assume files, schemas, routes, components, or libraries exist.

# Do not overwrite existing work without understanding it.

# Before modifying a database schema, inspect the current migration history.

# Before installing a dependency, determine whether the functionality can be implemented cleanly using the existing stack.

# Before changing architecture, explain why the change is necessary.

# Prefer incremental changes over large rewrites.

# Never leave the project in a broken state at the end of a task.

## don't be stupid rule

# Do not optimize for impressing me with complexity.

# I would rather have 500 lines of clean, understandable code than 2,000 lines of unnecessary abstraction.

# Do not introduce a library simply because it is popular.

# Do not introduce a service simply because large companies use it.

# Do not build for hypothetical millions of users before we have real users.

# Do not build features that do not improve the student experience or product operation.

# If a simple solution is reliable and scalable enough for our current stage, use the simple solution.
